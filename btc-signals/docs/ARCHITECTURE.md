# BTC Up/Down Signal App — Research Findings & Architecture Proposal

Status: **proposal, awaiting approval** (no app code written yet).
Research date: 2026-11-09, against live Polymarket production APIs.

The app is advisory only. It never signs, places, or cancels orders.

---

## 1. Research findings (verified live)

### 1.1 Market discovery

| What | How (verified) |
|---|---|
| Series | Gamma `series` slug `btc-up-or-down-5m` (id `10684`, recurrence `5m`) and `btc-up-or-down-15m` (id `10192`, recurrence `15m`) |
| Event slug | Deterministic: `btc-updown-5m-{start_unix}` / `btc-updown-15m-{start_unix}`, start aligned to 300 s / 900 s |
| Fetch | `GET https://gamma-api.polymarket.com/events/slug/{slug}` (or `/events?series_id=…&closed=…`) |
| Key market fields | `conditionId`, `clobTokenIds` (JSON string, `[Up, Down]`), `outcomes` `["Up","Down"]`, `eventStartTime`, `endDate`, `bestBid/bestAsk/spread`, `orderPriceMinTickSize` (0.01), `orderMinSize` (5), `acceptingOrders` |
| Resolution config | `cryptoMarketConfig = {"id":"btc-5m-twap-60","duration":"5m","twapEnabled":true,"twapLookbackSeconds":60}`, `resolutionMechanism:"oracle"`, `fallbackResolutionType:"none"` |
| Fees | `feesEnabled:true`, `feeType:"crypto_fees_v2"`, `feeSchedule={"rate":0.07,"exponent":1,"takerOnly":true,"rebateRate":0.2}`; CLOB `GET /fee-rate?token_id=` → `{"base_fee":1000}` |
| Outcome data | After close: event `eventMetadata = {"priceToBeat": …, "finalPrice": …}`, `outcomePrices` `["0","1"]` |

Markets are created about 24 h ahead (`startDate`), so the next window's token IDs can be pre-loaded.

### 1.2 Rules text (verbatim, identical for 5m and 15m today)

> This market will resolve to "Up" if the time-weighted average price (TWAP) of Bitcoin, generated by Chainlink, of the time range specified in the title is greater than or equal to the price at the beginning of that range. Otherwise, it will resolve to "Down". The resolution source … is … the BTC/USD TWAP data stream available at https://data.chain.link/streams/btc-usd-twap-60s-streams.

### 1.3 ⚠️ Mismatches with the brief

1. **The 5-minute markets use a 60 s TWAP, not 30 s.** Both 5m and 15m report `twapLookbackSeconds: 60` and the `btc-usd-twap-60s` stream. Polymarket's docs also say the 30 s TWAP feed has no replacement in the new socket. The model must take the lookback from each market's config, not hard-code it.
2. **The price to beat is also a TWAP, and windows chain.** Live data shows `priceToBeat(window N) == finalPrice(window N−1)` exactly, e.g. 74538.39136007415 appears as one window's `finalPrice` and the next window's `priceToBeat`. So the price to beat is the Chainlink 60 s TWAP at the window boundary, not a spot print.
3. **The rules wording is ambiguous.** "TWAP … of the time range specified in the title" could be read as a TWAP over the whole window. The structured config (60 s lookback) and the chained values both point to "60 s TWAP at the window end". The app will follow the structured config, store the raw rules text, and flag any market whose text or config differs from the known template.
4. **`priceToBeat` is not reliably in Gamma during the window.** In one sample it was `null` 4.75 minutes into a live 5m window. The app will compute the price to beat from the Chainlink TWAP feed at the window start and reconcile with Gamma once it appears.

### 1.5 Fees (docs.polymarket.com/trading/fees)

`fee_usdc = shares × 0.07 × p × (1 − p)`, charged to takers only (makers pay 0). That is 1.75¢ per share at p = 0.50 and 0.63¢ at p = 0.90. Selling early is also a taker trade, so a round trip pays the fee twice.

### 1.6 Historical data for the backtest

| Source | Use |
|---|---|
| Gamma `eventMetadata` (`priceToBeat`, `finalPrice`) for every closed window | Ground-truth labels and the true Chainlink TWAP at each boundary |
| Data API **v2** `GET https://data-api.polymarket.com/v2/trades?condition=…` (cursor pagination, snake_case) | Full trade tape per window, used to rebuild the odds path. **v1 was retired 2026-11-02** (returns an error) |
| CLOB `/prices-history` | Too sparse for closed markets (2 points per window). Not used |
| Coinbase `/products/BTC-USD/candles` (1m) and Binance Vision `klines` (1s) | BTC path inside each window |
| Our own recorder (live books + Chainlink ticks into SQLite) | Most realistic spreads and fills over time. Historical order books are not available anywhere else |

## 2. Architecture

```
                ┌──────────────────────── ingest (asyncio tasks) ────────────────────────┐
 Coinbase WS ──▶│ spot.py  (trades → 1s/1m candles, VWAP, OFI)     ◀── failover ──▶ Binance │
 RTDS/PolyBolt ▶│ chainlink.py (spot + 60s TWAP; price-to-beat capture at boundary)        │
 CLOB WS ──────▶│ polymarket_ws.py (books, best bid/ask, trades for current+next windows)  │
 Gamma REST ───▶│ discovery.py (slug calc, rules parse + validation, pre-load next window) │
 Deriv REST/WS ▶│ derivs.py (funding, OI, liquidations, perp book imbalance) — pluggable   │
 RSS/calendar ─▶│ news.py (headline sentiment) + calendar.py (CPI/FOMC/NFP blackouts)      │
                └──────────────┬──────────────────────────────────────────────────────────┘
                               ▼  in-memory State (single event loop, no locks)
                ┌──────────────────────────────┐   every 1 s per window
                │ features.py → model.py P(UP) │──▶ signal.py (edge vs ask+fee+buffer, gates)
                └──────────────────────────────┘          │
                               ┌──────────────────────────┼────────────────────┐
                               ▼                          ▼                    ▼
                      positions.py (SELL/HOLD)     paper.py → SQLite     FastAPI WS → dashboard
```

### 2.2 Rules validation (`rules.py`)

For every discovered market, parse `description`, `resolutionSource` and `cryptoMarketConfig` into a `RuleSpec(asset, duration, twap_lookback_s, comparator=">=", source_url)`. Compare it with the expected template: `twapEnabled`, lookback in {60} (configurable), the `>=` "greater than or equal" wording, a Chainlink source, and `resolutionMechanism == "oracle"`. On any mismatch, the window is forced to **NO TRADE** and the dashboard shows a red **RULES MISMATCH** banner with the diff. This covers both the 30 s assumption and future rule changes.

### 2.3 Prices and gaps

- **Reference price (resolution truth):** the Chainlink 60 s TWAP from RTDS. PolyBolt is used instead if credentials are present or RTDS is gone. If neither is available, a synthetic 60 s TWAP computed from Coinbase 1 s prices is used, marked as degraded.
- **Spot:** Coinbase as the primary source, Binance (or Binance.US) as secondary, chosen in config. A feed counts as "down" if it is silent for more than 3 s; then the other one is used and an alert fires.
- **Gap tracker:** rolling `chainlink − coinbase`, `chainlink − binance`, and `market_implied_p − model_p`, shown on the dashboard and stored. The model works in Chainlink terms: spot moves are translated with an EWMA basis estimate.

### 2.4 Features (`features.py`, all pure functions)

- `d_sigma = (ref_now − price_to_beat) / (σ_1s · √τ_eff)`, where σ is realised 1 s volatility (EWMA, about 15 min half-life). `τ_eff` is TWAP-aware: before the final lookback starts, `τ_eff = (τ − L) + L/3`. Inside the final L seconds, part of the TWAP is already locked in, so the expected final value combines the locked average with the unlocked remainder, whose variance is `σ²·r³/(3L²)` for `r` seconds left. This matters most for 5m windows, where the 60 s TWAP covers 20% of the window.
- Time remaining (fraction and seconds); 1m/3m/5m log returns; VWAP deviation (session and window); RSI(14) on 1m; order-flow imbalance (signed trade volume, 30 s/60 s); top-of-book imbalance on spot; realised vol and vol-of-vol.
- Derivatives: funding rate, ΔOI 5m, net liquidations over 5 min, perp book imbalance.
- News: decayed sentiment score in [−1, 1] × confidence.
- Market-microstructure context (not used as a model input, to avoid circularity): Polymarket mid and spread.

### 2.5 Model (`model.py`)

- **Prior:** `p0 = Φ(d_sigma)`, a driftless Brownian motion with the TWAP adjustment. It is fully explainable and already strong.
- **Model:** logistic regression on `logit(p0)` plus the standardised features above, with L2 regularisation and separate models for 5m and 15m. Each driver is reported as `coef × value`, so the "top 3 drivers" fall out directly. Gradient boosting (sklearn `HistGradientBoosting`) is an optional config switch, explained with per-feature contributions.
- Trained offline by `backtest/collect.py`, then `train`. Saved as JSON (coefficients plus scaler) so it is human-readable.
- Reported calibration (reliability curve, Brier score). If held-out calibration is poor, isotonic recalibration is applied.

### 2.6 Entry signal (`signal.py`)

For each side s ∈ {UP, DOWN}: `edge_s = p_model_s − ask_s − fee_per_share(ask_s) − slippage_est − buffer`, with `buffer` defaulting to 0.04. `slippage_est` is computed by walking the live book to `stake_usd`. Signal the side with `edge > 0` only if all gates pass:

- rules OK, feeds healthy, and the price to beat captured
- no blackout from the calendar (default −5 min / +10 min around CPI, FOMC decision and press conference, NFP, PCE, GDP)
- no news shock (high-confidence headline in the last N minutes, configurable)
- time remaining within [min, max] (e.g. not in the final 10 s, when books thin out)
- book depth ≥ stake, and spread ≤ max_spread

Otherwise **NO TRADE**, with the blocking reason shown.

### 2.7 Exit engine (`exits.py`)

You record a manual position in the UI (side, entry price, shares). Every 2 s the engine computes `fair = p_model(side)` and `exit_bid = best bid after walking the book − exit fee`:

- **SELL — edge gone:** `exit_bid ≥ fair − hold_buffer`. The market already pays fair value or more, so holding adds risk without edge.
- **SELL — stop:** `fair` has fallen below `entry − stop_threshold` (or `d_sigma` crossed back past a configurable level).
- **SELL — lock profit:** `exit_bid ≥ entry + take_profit` and the remaining EV of holding (`fair − exit_bid`) is below the lock threshold.
- **HOLD:** otherwise, with the reason (e.g. "fair 0.91 vs bid 0.84: +7¢ edge persists").

A SELL/HOLD change is pushed as an alert.

### 2.8 Storage (SQLite, `aiosqlite`)

Tables: `windows` (slug, duration, start/end, price_to_beat, final_price, outcome, rules_ok, rules_diff), `ticks` (sampled every second: ref/spot/up_bid/up_ask/… for replay), `signals` (ts, window, side, p_model, p_mkt, edge, drivers JSON, gates JSON), `paper_trades` (entry/exit/fees/pnl), `positions` (manual), `news` (headline, source, label, confidence), `feed_health`.

### 2.9 Backtester

1. `collect` gets N days of closed windows: Gamma outcomes (`priceToBeat`/`finalPrice`), v2 trade tapes, and Coinbase/Binance-Vision candles.
2. `replay` rebuilds features at each second of each window, with no look-ahead, using only data with `ts ≤ t`.
3. **Fill model:** without historical books, the ask is the last trade price plus a half-spread (median spread observed by the recorder; default 1 tick, plus a size-dependent impact), and a fill counts only if trades printed at or through that price within a short latency (default 2 s). Fees use the exact curve. Once the recorder has data, replay uses the actual recorded books instead.
4. Train/test split by time (walk-forward), never random.
5. Report: number of trades, win rate, average edge at entry, realised EV per trade and per $, max drawdown, Sharpe per window, a calibration chart (predicted-probability deciles vs realised frequency), and an edge-bucket breakdown.

### 2.10 Paper trading

Always on. Every signal becomes a paper trade at the live ask (walking the book) with fees. Exits follow the exit engine or hold to resolution, and both PnL paths are logged. Each trade is settled against Gamma `eventMetadata` once the window closes. The dashboard shows running stats. The README recommends at least 300 windows before any real money.

### 2.11 Dashboard (plain HTML/JS, served by FastAPI)

Two cards (5m, 15m) showing: countdown, price to beat, Chainlink TWAP, spot, gap, model P(UP), market odds, edge, the **signal in large text**, and the top 3 drivers. Also: a position panel (enter a position, live value, SELL/HOLD plus reason), a paper stats panel (win rate, EV, drawdown, calibration mini-chart), and a feed-health strip. A WebAudio beep plus the Notification API alert on new signals and SELL changes. Live updates over a single `/ws` push socket.

### 2.12 News and calendar

- **News:** RSS (CoinDesk, Cointelegraph, The Block, Decrypt) polled every 60 s, plus an optional CryptoPanic API (token in `.env`). The classifier is a transparent crypto-finance lexicon with rules (e.g. "ETF approval", "hack", "exploit", "liquidation", "rate cut"), giving a label and confidence. An optional LLM classifier can be enabled later.
- **Calendar:** a bundled `events.yaml` with 2026–27 FOMC/CPI/NFP/PCE dates (from the Fed and BLS schedules), plus an optional weekly JSON calendar feed. Blackout windows are configurable per event type.

### 2.13 Derivatives source

Binance futures is geo-blocked in the US. Proposed: a pluggable provider with **Hyperliquid** (public, no key: funding, OI, L2 book) as the default and **Binance futures** as an option (funding, OI, `forceOrder` liquidation stream) if it's reachable for you. Liquidations are best-effort: they're missing on Hyperliquid's public REST, so that feature is set to 0 when unavailable.

### 2.14 Tech

Python 3.11+, FastAPI, uvicorn, `websockets`, `httpx`, `aiosqlite`, numpy/pandas, scikit-learn, pydantic-settings, `feedparser`, pytest + pytest-asyncio. No trading SDK is a dependency.
